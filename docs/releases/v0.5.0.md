## v0.5.0

This release makes the engine-mode client a real player. It joins servers, moves, presses keys and clicks, breaks and places blocks, opens GUIs, plays sounds, and runs against dedicated servers in CI. World rollback between scenarios now happens in place, without a restart.

### Real client and multiplayer

- **Real join (#167).** An engine-mode client boots the full game client and joins a server offline. Character creation picks an appearance and a class (`commoner` by default).
- **Game-thread lifecycles (#168).** Scenario lifecycles run on the client's and the server's own game threads.
- **Headless players (#169).** `CreateTestPlayerAsync` joins headless players as real multiplayer connections, packet by packet.
- **What each player received (#170).** `ReceivedPackets` records chat, entities arriving and departing, particles, sounds, block highlights, block changes, and mod network packets decoded by message type.

### Input, world and GUI

- **Real input (#171).** `PlayerControls` and `VirtualInputController` drive the client through its own keyboard and mouse handling, whatever the key bindings.
- **Blocks (#172).** `session.Blocks` breaks, places and uses blocks through the client's own block selection and interaction packets, so reach checks, permissions and mods' handlers run as in the game.
- **One click (#180).** A use or a placement is one click, whatever the frame rate.
- **GUI and inventory (#173).** `HeadlessClient.Ui` reads and drives the live GUI and inventory, with real clicks at element centres.

### Audio, network, bridge and settings

- **Sounds (#174).** `HeadlessClient.Sounds` records every sound the client plays, with location, position, volume and range.
- **Recorded, degradable link (#175).** Engine-mode traffic goes through a `LoopbackLink`:
  - `PacketRecorder` captures both directions;
  - `NetworkDegradation` applies latency, jitter and drops;
  - `DisconnectSimulator` disconnects for real.
- **Bridge and logged errors (#176).** The bridge mod loads in engine-mode clients. `Logs` captures what the client and the server log, and scenarios can fail on unexpected errors with `FailOnLoggedErrors`.
- **Live settings (#177).** `HeadlessClient.Settings` changes client settings live. `[ClientSettingsMatrix]` runs a test once per graphics preset.

### Real TCP, auth, dedicated servers and CI

- **TCP and auth (#178).** The embedded server listens on real TCP and UDP sockets. `ClientAuth` joins offline or with an account session (`FromEnvironment` reads one from the environment). `ConnectTcp` and `ConnectRemote` join servers over the network.
- **Dedicated server (#179).** `docker/dedicated-server` builds a dedicated server for tests: offline auth, no whitelist, a creative superflat world. `start-server.sh` runs the same configuration where there is no Docker. `RemoteServerTests` and a new CI job run against it. See `docs/ci-and-cloud.md`.

### In-place world rollback

- **Snapshot and restore (#180).** `WorldSnapshot` holds:
  - every loaded chunk in the game's save format;
  - the height maps of their map chunks;
  - every player's world data;
  - the position, game mode and inventories of connected players.

  `RestoreSnapshot` swaps only the chunks that changed and sends them to joined clients again.
- **What `WorldIsolation.Rollback` now does:** it keeps the server running between the tests of a class. In client-server scenarios it also keeps the joined client and its connection, restoring the world after each test.

### Tiered CI and gated releases

- **Traits (#182).** Scenario attributes mark their tests `Category=Live`, and `PharosTraits` names the traits. Run the quick tests alone with `dotnet test --filter "Category!=Live"`.
- **Two CI lanes (#182).**
  - A pull request runs the quick lane on Linux, in a few minutes.
  - The full suite on Linux, Windows and a dedicated server runs on main, every night, by hand, and for pull requests labeled `full-ci`.
- **Gated release (#182).** The Release workflow runs the full suite first, then publishes to NuGet and creates the GitHub release only when all of it passes.

### Fixes

- **Tessellation:** fixture-mode clients open the vanilla render pass and start the tesselator the chunk manager actually uses (#153). Optimum tessellation is covered in the headless client (#151, #152).
- **Platform and formatting:** headless clients survive a Wayland session, the Linux SkiaSharp native library is staged, and numbers are parsed and formatted with the invariant culture.
- **Flaky tests on slow CI runners:** they now wait for the conditions they depend on, not for a fixed time.
- **Settings watchers:** a disposed client's client-settings watchers are removed, so a later client changing a setting no longer runs them against a dead client (#182).

### Breaking changes

- **`LiveBlockInteraction.UseAsync`:** returns `Task<bool>`, whether the client acted on the click. Its second parameter is now `maxFrames` (it was `holdFrames`).
- **`WorldSnapshot.ChunkData`:** keyed by the 3D chunk index (`long`).
- **`EmbeddedServerHost.RestoreSnapshot`:** returns how many chunks it restored.
- **Host reuse:** scenario classes without an explicit isolation (`Rollback` is the default) now reuse their server, and in client-server scenarios their client, between tests. A class that needs a fresh boot per test sets `WorldIsolation.Restart`.
- **Direct boots:** booting a client or a server directly disposes the host a scenario kept for its next test.
