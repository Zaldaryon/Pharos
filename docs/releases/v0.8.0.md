## v0.8.0

### UI and HUD inspection

- **HUD driver (#263).** `Client.Hud` reads every element of the in-game HUD: statbars (health, satiety, oxygen), hotbar (slots, selection, offhand), coordinates, block info, and custom mod elements.
  - `Element<T>()` returns any HUD element by its exact dialog type or a fuzzy name search.
  - `Elements()` enumerates all visible HUD elements with their bounds and visibility state.
  - `WaitForAsync` ticks until a predicate on the HUD state becomes true, with a frame budget and timeout.
  - See "HUD inspection" in `docs/hud.md`.

- **Block entity dialogs (#266).** `Client.BlockEntityDialog` opens and interacts with block entity GUIs: firepits, barrels, traders, signs.
  - `Slots()` returns real inventory slots with bounds, item stacks, and interaction state.
  - `Click(slot, modifiers)` sends left, right, middle clicks with Shift/Ctrl/Alt modifiers.
  - See "Block entity dialogs" in `docs/engine-mode.md`.

- **Inventory slots (#269).** `Client.Slots` inspects and manipulates player inventory slots.
  - `Bounds()` returns real slot pixel bounds for UI assertions.
  - `Wheel(delta)`, `DoubleClick()`, `HotbarSwap(index)`, `DropAll()` simulate all slot interactions.
  - See "Inventory inspection" in `docs/engine-mode.md`.

- **Text input (#273).** `Client.Text` drives text input fields with full Unicode support.
  - `PerCodePoint()` handles multi-byte characters correctly.
  - `ImeCommit()` simulates IME composition commits.
  - `Client.Clipboard` integrates with the game's clipboard API when available.
  - See "Text input" in `docs/engine-mode.md`.

### Rendering and graphics inspection

- **Camera driver (#277).** `Client.Camera` reads the actual camera state.
  - `EyePosition` returns the true eye position (not player position).
  - `Mode` returns the current camera mode (first-person, third-person, etc.) via reflection.
  - See "Camera inspection" in `docs/engine-mode.md`.

- **Pipeline driver (#280).** `Client.Pipeline` inspects the render pipeline.
  - `CapturePixels(x, y, w, h)` captures framebuffer pixels to an array.
  - `Framebuffers()` lists all active framebuffers with dimensions and attachments.
  - `RenderStages()` enumerates the pipeline's render stages.
  - See "Render pipeline" in `docs/engine-mode.md`.

- **Shader driver (#283).** `Client.Shaders` inspects shader programs.
  - `Uniforms(program)` lists all uniform variables with types and values.
  - `Includes(program)` traces shader include dependencies.
  - `CompileStatus(program)` reports compilation and linking status.
  - `ModShaders()` enumerates shaders registered by mods (excludes vanilla `EnumShaderProgram`).
  - See "Shader inspection" in `docs/engine-mode.md`.

- **Entity driver (#285).** `Client.Entities` inspects entity rendering state.
  - `ActiveAnimations(entity)` lists currently playing animations with progress.
  - `GearAttachments(entity)` enumerates equipped gear attachment points.
  - See "Entity rendering" in `docs/engine-mode.md`.

### Weather and environment

- **Sky, ambient and weather (#290).** `Client.Weather`, `Client.Sky`, and `Client.Ambient` read actual game rendering state, not placeholder values.
  - `WeatherSnapshot` now uses the active render inputs (`clientClimateCond.Rainfall`, `BlendedPrecType`, wind from `BlockAccessor.GetWindSpeedAt`) instead of obsolete zero-valued fields.
  - `CloudCoverage` and `LightningFlashes` (via `simLightning.lightningFlashes`) are now populated.
  - `SkySnapshot` uses actual `SunPosition`/`MoonPosition` and `SunColor`/`ReflectColor` from the sky renderer.
  - `AmbientSnapshot` includes `LerpSpeed` modifier values and `FlatFogYOffset + SeaLevel`.
  - `FreezeSkyAsync` requires an embedded host, freezes the calendar, stills wind, stops weather changes, and waits for calendar sync and full ambient blend.
  - See "Weather inspection" in `docs/engine-mode.md`.

- **Weather particle attribution (#290).** `ParticleAttributionHooks` uses Harmony patches on `WeatherSimulationParticles.SpawnRain/Snow/Hail/Dust` to count weather-specific particle spawns separately from other quad particles.
  - `WeatherSnapshot.WeatherParticleSpawns` provides per-type particle spawn counts.
  - See "Particle attribution" in `docs/engine-mode.md`.

### Audio inspection

- **Sound recorder (#293).** `Client.Sounds` records and inspects sound playback.
  - `StillPlaying` now correctly excludes stopped and disposed loops.
  - `Audibility` measures actual volume attenuation.
  - See "Sound inspection" in `docs/engine-mode.md`.

- **Music driver (#293).** `Client.Music` inspects the music system.
  - `CurrentTrack` returns the currently playing music track.
  - `State` returns playback state (playing, paused, stopped).
  - `Volume` returns the current music volume.
  - See "Music inspection" in `docs/engine-mode.md`.

- **Ambient sound driver (#293).** `Client.AmbientSounds` inspects ambient sounds.
  - `ActiveSounds()` lists all playing ambient sounds with their positions and volumes.
  - `Count` returns the number of active ambient sounds.
  - See "Ambient sounds" in `docs/engine-mode.md`.

- **Audio levels (#293).** `Client.AudioLevels` reads the game's audio level settings.
  - `Master`, `Music`, `Ambient`, `Weather`, `Blocks`, `Creatures`, `Player`, `Gui` volume levels.
  - See "Audio levels" in `docs/engine-mode.md`.

### xUnit v3 and testing framework

- **xUnit v3 parity (#327).** Full parity with xUnit v3 test execution model.
  - `TestContext.Current.CancellationToken` flows through all Pharos async waits.
  - Failure artifacts are attached via `TestContext.AddAttachment` with correct media types.
  - `WindowSizesAttribute` and `ClientSettingsMatrixAttribute` produce `TheoryDataRow`s with `TestDisplayName` and per-row `Skip`.
  - See `docs/xunit-v3.md`.

### GL draw call capture

- **GL command proxy (#363).** Comprehensive GL draw call interception.
  - Patches all generic type variants (int, uint, short, ushort, byte, sbyte, float, double, IntPtr).
  - Covers `DrawTransformFeedback*`, `DrawArraysIndirect`, `DrawElementsIndirect`, and all instanced/base variants.
  - `ShaderProgramBindings`, `TextureBindings`, `VaoBindings`, `FramebufferBindings` track state binding counts.
  - `DrawCallsByMethod` provides a breakdown of draw calls by GL method name.
  - `GetDiagnosticReport()` returns a formatted diagnostic report.
  - `PrePatchDrawMethods()` pre-patches GL methods before JIT compilation.
  - `VerifyPatches()` confirms patches are active.
  - Integrated into Pharos startup for automatic early patching.
  - See "GL capture" in `docs/engine-mode.md`.

### Memory and mesh pool inspection

- **Chunk render pools (#364).** `MemoryInspector.ChunkRenderPoolSnapshot()` reads the actual chunk renderer mesh pools.
  - `TotalVerticesAllocated/Used`, `TotalIndicesAllocated` from `ChunkRenderer.masterPool`.
  - `TotalRenderedTriangles`, `TotalAllocatedTriangles` computed from pool state.
  - `EstimatedVideoMemoryBytes`, `AverageFragmentation` for memory analysis.
  - `ByRenderPass` breakdown (Opaque, Liquid, TopSoil, etc.).
  - `PendingRemovalCount` for pool cleanup tracking.
  - See "Memory inspection" in `docs/engine-mode.md`.

### Platform loop execution

- **Platform loop stepper (#365).** `Client.PlatformLoop` invokes the full platform render loop.
  - `StepAsync()` calls `ClientPlatformWindows.window_RenderFrame` for complete frame pacing.
  - `PlatformStepResult` with `Supported`, `UnsupportedReason`, `FramePacingActive`.
  - `FramePacingSnapshot` captures VSync mode, max FPS, and pacing state.
  - Available only in engine mode with a window.
  - See `docs/platform-loop.md`.

### Documentation generator

- **Literal preservation (#290).** The documentation test generator (`scripts/generate-doc-tests.py`) now uses token-aware masking for C# string literals, comments, and characters.
  - Preserves whitespace-only lines inside verbatim and raw strings.
  - Does not extract `using`-like text from inside string literals.
  - Does not rewrite attribute or type names inside ordinary, raw, or interpolated strings.
  - See "Documentation tests" in `CONTRIBUTING.md`.

### Bug fixes and follow-ups

- **Weather field reads (#290).** Fixed `WeatherDriver` to use active render inputs instead of obsolete `WeatherDataSnapshot.PrecIntensity` and `nowPrecType` fields which were always zero.
- **Ambient blend wait (#290).** Fixed `AmbientDriver.WaitForBlendAsync` to compare all blended components with proper frame budget and explicit `TimeoutException`.
- **Sound lifecycle (#293).** Fixed `SoundRecorder.StillPlaying` to exclude loops that have been stopped or disposed.
- **Freeze synchronization (#290).** Fixed `FreezeSkyAsync` to properly freeze calendar, still wind, stop weather changes, and wait for calendar sync before returning.
